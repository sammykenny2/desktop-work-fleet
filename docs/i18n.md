# Internationalization

Work Fleet is written in English first. Every user-visible string comes from a locale catalog, and the user can
pick the display language in Settings > General > Display language.

## Locales and the language preference

- Supported locales: `en` (the default and the fallback for any missing text) and `zh-TW`.
- The preference is `auto`, `en` or `zh-TW`; a new device starts at `auto`. It belongs to the device, like window
  placement: it is never part of a profile, a backup or Google data.
- Where it is stored:
  - Windows, macOS and Linux: the `language` field of the host's `host-preferences.json`.
  - Android: the activity's private preferences (key `language`).
  - iOS: the app's user defaults, copied into the App Group's defaults so the Share Extension draws its text in the
    same language; the extension falls back to its own defaults and then to `auto`.
  - Browser preview: `localStorage` key `work-fleet.language`. When storage is unavailable the choice still applies to
    the open window.
- `auto` walks the system's preferred languages in order and takes the first one that matches:
  - `en` and any `en-*` tag map to `en`.
  - `zh`, `zh-TW`, `zh-Hant`, `zh-HK`, `zh-MO`, and tags that start with `zh-TW-`, `zh-Hant-`, `zh-HK-` or `zh-MO-`,
    map to `zh-TW`.
  - Simplified Chinese (`zh-CN`, `zh-Hans`, `zh-SG`, ...) and every other language do not match; the walk continues.
  - Nothing matching means `en`.
  - Matching ignores case, treats `_` like `-`, and drops a POSIX encoding or modifier (`zh_TW.UTF-8` is `zh-TW`).
- The renderer (`matchLocale` and `resolveLocale` in `src/i18n/index.js`) and every native host apply exactly these
  rules, so the tray, menus and dialogs a host draws itself always match the window.

### Settings

Settings > General has one row, **Display language**, with a select. As in the Cats apps, each option is named in the
current UI language and "Auto-detect" never names the language it resolved to:

- English UI: `Auto-detect`, `English`, `Traditional Chinese`.
- Traditional Chinese UI: `自動偵測`, `英文`, `繁體中文`.

Choosing an option stores it, switches the window at once without reloading, and asks the host to redraw its tray,
menus and dialogs.

## Renderer catalogs

- `src/i18n/index.js`: `t(key, values)`, `plural(key, count, values)`, `formatDate(value, options)`,
  `setLocale`, `getLocale`, `onLocaleChange`, `localizeDocument`, `matchLocale`, `resolveLocale`. It is import-safe
  in Node and in every WebView; nothing touches the DOM at load time, and the locale is `en` until something sets it.
- `src/app/language.js` connects the preference to the main window: `startLanguage()` applies the browser's
  languages first, `adoptHostLanguage(native)` switches to the host's stored preference and system languages, and
  `changeLanguage(value)` stores a new choice.
- `src/i18n/locales/<locale>/<area>.js` export flat objects. Every key starts with its file's name and a dot
  (`settings.general.language` lives in `settings.js`, `errors.core.groupLimit` in `errors.core.js`), and
  `src/i18n/catalogs.js` merges the areas. Every locale has the same files, keys and placeholders.
- Key names are dotted camelCase after the area prefix: `<area>.<section>.<name>`. `nativeErrors.<code>` keys use the
  host's kebab-case error code as the last part.
- Placeholders are `{name}`. A missing value leaves the placeholder visible. Never build a sentence by concatenating
  translated fragments; give the whole sentence one key with placeholders, because word order differs.
- Plurals: `plural('app.noteCount', n)` picks `app.noteCount.one` or `app.noteCount.other` with `Intl.PluralRules`.
  Both keys exist in every locale, even where the language has one form.
- Dates and times: `formatDate(value, options)` formats in the current locale. Never pass a hard-coded locale to
  `toLocaleString`.
- A missing key falls back to English, and a key missing from English returns the key itself. Tests fail before
  either happens.

### Static markup

HTML holds no UI text of its own. `data-i18n="key"` sets an element's text, and
`data-i18n-attr="aria-label:key;title:key;placeholder:key"` sets attributes. `localizeDocument()` fills both at startup
and after every language change.

### Dynamic text

Code builds text with `t()` at the moment it renders. After a language change, `onLocaleChange` listeners redraw:
the main window calls `relocalize()` in `src/app/main.js`, which re-renders the views and an open settings dialog.
Status lines already on screen keep their language until their next update.

### Error messages

- Shared JavaScript (`src/core`, `src/sources`, `src/layout`, `src/backup`, `src/storage`, `src/native/*.js`,
  `src/desktop`) throws `FleetError(code, message)` through `requireValue(condition, code, message)`, with the
  message from `t()` at the moment it throws: `requireValue(ok, 'stale-layout', t('errors.common.layoutChanged'))`.
  The code stays a stable English identifier for logic; the message is the localized text the UI shows.
- Keys live in `errors.<area>.*` (`errors.core`, `errors.sources`, `errors.backup`, `errors.storage`,
  `errors.desktop`). A sentence that several modules share goes once into `errors.common.*`.
- Error messages are complete sentences that tell the user what happened and what to do, as before.

## Native hosts

### Protocol

- `host.info` reports `capabilities.languagePreference: true` and
  `language: { preference: 'auto' | 'en' | 'zh-TW', system: string[] }`, where `system` lists the operating system's
  preferred UI languages as BCP 47 tags, most preferred first.
- `host.language.set { preference }` stores the preference, re-resolves the host's own locale, redraws the tray,
  menus and any open host dialog, and replies with the new `{ preference, system }`.
- Desktop scenes get the locale from the main window: each projected frame carries `locale`, and the scene applies it
  before drawing.
- See `contracts/native.d.ts`.

### Text a host draws itself

A host resolves its locale at startup from its stored preference, before any window opens. That matters at sign-in
starts, where the tray appears long before the main window. The host uses that locale for:

- tray, menu bar and application menus;
- native dialogs, alerts and message boxes;
- file picker titles and notifications;
- descriptive text it returns for the page to show, such as the reason desktop papers or start-at-login are
  unavailable, or why sync is paused.

Each host keeps one small string table with an English and a Traditional Chinese block, in a fixed format that
`tests/i18n.test.js` reads to check that both blocks have the same keys and placeholders:

- Windows: `src/native/windows/core/HostText.cs`.
- Linux: `src/native/linux/text.py`.
- macOS and iOS: `src/native/apple/Shared/FleetText.swift`.
- Android: `src/native/android/app/src/main/java/app/workfleet/nativehost/HostText.java`.

Each table starts a locale block with a line containing the marker `i18n:en` or `i18n:zh-TW` and ends it with a line
containing `i18n:end`, in that language's comment syntax. Between the markers, each entry is on its own line, and the
key is the first double-quoted string on that line. Placeholders use `{name}`, as in the renderer.

### Errors from hosts

A host answers a failed request with `{ code, message }`, where `message` is English and `code` is a stable
kebab-case identifier. `nativeError()` in `src/native/bridge.js` turns the reply into a `FleetError`:

- with a `nativeErrors.<code>` catalog entry, the message is that entry in the UI language;
- otherwise it keeps the host's English message.

Every code a host can send needs a `nativeErrors.<code>` entry; `tests/i18n.test.js` scans the host sources for error
codes and lists any that lack one. When one code covers several situations, the entry describes them all; give a
situation its own code when the user needs to act differently.

### The 0.1.0 validation prototype

`src/web`, `src/server` and `src/macos` are the frozen 0.1.0 prototype (ADR-002). Their text is plain English in the
code and stays outside the catalogs and the language setting.

## Writing style and terminology

English text is short, plain and in sentence case ("Sync now", not "Sync Now"). Buttons are verbs; status lines say
what happened and, when the user must act, what to do. The Traditional Chinese catalogs keep the wording the app
used before English came first. Use the same term for the same thing everywhere, including the native tables:

- note (便箋); the board (便箋牆) and the list (清單) are the two main-window views; desktop notes (桌面便箋).
- group (群組), My groups (我的群組), My notes (我的便箋, the default group name), group regions (群組區域),
  rows (列) and columns (欄).
- Capture (記下想法) for the new-note button, Quick capture (快速記錄) for the shortcut and tray item.
- Locked (鎖定) and Adjust (調整): Adjust this group (調整此組), Adjust all (調整全部), Done (完成).
- Stack (堆疊), Spread (攤開), Undo (復原), Arrange (排列).
- Wallpaper layer (桌布層), Desktop layer (桌面層), Top layer (最上層), Adjust position (調整位置).
- draft (草稿), Unfinished drafts (未完成草稿), Share inbox (分享收件匣), Versions and conflicts (版本與衝突).
- Filters: To do (待處理), Completed (已完成), Archived (封存), Deleted (刪除區).
- main window (主畫面), tray (系統匣) on Windows and Linux, menu bar (選單列) on macOS.
- Settings pages: General (一般), Account and sync (帳號與同步), Data and backup (資料與備份), Desktop (桌面),
  Shortcuts (快捷鍵); the update section is Version and updates (版本與更新).
- sync (同步), Sync now (立即同步), Local notes (本機便箋), keyring (金鑰圈).
- backup (備份), restore (還原), export (匯出), import (匯入), attachment (附件), checklist (checklist).
- Reset desktop layout (重置桌面佈局).

## Tests and the CJK guard

`tests/i18n.test.js` checks that:

- every locale has the same area files, keys and placeholders, with no empty text;
- every key starts with its area's prefix;
- every literal `t('...')` and `plural('...')` key in `src/` and every `data-i18n` key in HTML exists in English;
- every native error code has a `nativeErrors.*` entry, and every native string table has matching blocks;
- no tracked file contains Chinese text outside the zh-TW catalogs, Chinese editions of documents (`*.zh-TW.*`,
  `*_ZH.*`), the native tables' zh-TW blocks, and the short list of exceptions in the test. Each exception says why it
  needs Chinese, for example a persisted protocol value or a test of CJK text handling.

Automated UI tests run in English. Browser probes open with `locale: 'en-US'`, and native probes store the
preference `en` before the app starts.

## Adding a locale

1. Add the locale to `LOCALES` in `src/i18n/index.js`, its matching rule to `matchLocale`, and the same rule to every
   host.
2. Copy every area file under `src/i18n/locales/en/` to the new locale's folder, translate it, and import it in
   `src/i18n/catalogs.js`.
3. Add a block to each native string table and an option to the Display language select.
4. Run `node --test tests/i18n.test.js`.

## The initial group name

The group a new Google workspace starts with is generated identically on every device, and its name is part of
the revision bytes that devices compare during initialization (ADR-053, ADR-054). Its stored name therefore stays
the original Chinese value, `INITIAL_GROUP_NAME` in `src/sources/initial-group.js`, regardless of the UI language.
`groupName(group)` in `src/core/group-name.js` shows any group that still has exactly that name, including first
groups that earlier versions created with the same text, under the localized `app.groups.defaultName` until the user
renames it. Every place that shows a group name uses `groupName()`. Groups created on one device, such as the local
workspace's first group, take the localized name when they are created.
